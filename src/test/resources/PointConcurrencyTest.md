# Point 동시성 통합 테스트

## 개요
이 테스트는 Java + Spring Boot 환경에서 사용자 포인트 시스템의 동시성 이슈를 방지하고, 안정적인 처리를 보장하기 위해 작성되었습니다.  
100개의 요청이 동시에 들어와도 정확하게 포인트가 반영되고, 잔액 부족 시 적절히 차단되며, 여러 사용자의 충전/사용 요청도 독립적으로 처리됨을 검증합니다.

---

## 사용 언어 및 동시성 제어 방식

- 언어: Java
- 프레임워크: Spring Boot (MockMvc, @SpringBootTest)
- 동시성 제어 방식:
    - `synchronized` 키워드 또는 Java의 `ReentrantLock` 등을 활용한 비즈니스 로직 내 동기화 처리 (서비스 레이어에서 적용)
    - 테스트 코드에서는 `ExecutorService`와 `CountDownLatch`를 활용해 명시적인 동시 요청 환경을 구성

### 장점
- 명시적인 병렬 환경 구성으로 실제 서비스와 유사한 테스트 시나리오 가능
- `MockMvc` 사용으로 전체 통합 레이어 테스트 가능
- 객체지향적인 설계와 책임 분리 원칙(SRP)을 기반으로 로직 구성 → 테스트가 간결해짐
- TDD 기반 작성: 실패하는 테스트를 먼저 만들고, 로직을 리팩토링하며 완성

###  단점
- 실제 WAS 레벨의 동시성 테스트보다 제한적일 수 있음 (단일 JVM, 테스트용 쓰레드 풀)
- `In-Memory` DB를 사용하기 때문에 실제 DB 트랜잭션 경합 상황과는 다를 수 있음
- 테스트 환경 설정 및 초기화 로직이 복잡해질 수 있음 (`Reflection`으로 내부 상태 초기화)

## 테스트 설명

### 1. 동일 사용자 충전 100건 동시 요청
- 목표: 잔고 누락 없이 정확히 100건 * 100원 = 10,000원이 적립되는지 확인
- `CountDownLatch`로 100개의 요청을 동시에 발사
- 요청 성공 시 최종 잔고를 검증

### 2. 잔액 부족 상황에서 동시 사용 요청
- 목표: 일부 요청은 실패하더라도 잔액이 음수가 되지 않음을 보장
- 실패 응답은 `409 Conflict`로 처리
- 최종 잔고는 0원 이상이며, 소모 금액은 예상 가능한 범위 내

### 3. 다중 사용자에 대한 충전/사용 요청
- 목표: 여러 사용자가 동시에 충전 및 사용을 요청해도 각자의 포인트가 독립적으로 처리됨을 보장
- 10명의 사용자 * 20회 충전 + 20회 사용
- 각 사용자 최종 포인트: `100*20 - 50*20 = 1000원`

## 개발 원칙

### ✅ FIRST 원칙 (테스트 코드 품질 원칙)
- Fast: 단위 수준에서 빠르게 실행
- Independent: 서로 독립적, `@BeforeEach`로 상태 초기화
- Repeatable: 매번 같은 결과 보장
- Self-validating: 결과 검증 포함
- Timely: 로직 구현 전에 테스트를 먼저 작성 (TDD 기반)

### ✅ 객체지향 설계
- 포인트 테이블과 히스토리 테이블을 역할에 따라 분리하여 단일 책임 유지
- 서비스 레이어 내부에서 락 제어 또는 트랜잭션 처리를 담당 (단일 진입점 설계)
- 테스트는 외부에서 행위만 검증하며 내부 구현에 의존하지 않음
